# Проверка NEXUS OS / Studio 6.7.0

29 октября 2026. Проверки хостовые, с заменителями аппаратных библиотек.

## Выполнено

- Восемь C++ наборов: основная регрессия, активность, навигация, аудит кнопки/сна/уведомлений, профиль батареи, новый USB-протокол, OSD-компоновка. Строгие предупреждения компилятора, AddressSanitizer и UndefinedBehaviorSanitizer.
- Новые команды проходят через настоящий обработчик themeSerialService: проверены диапазоны, запрет лишних аргументов, пять будильников, календарь, таймер, сохранение палитры/информационных полей/звука, подтверждения удаления, ошибки NVS, CRC и чтение фона.
- JavaScript всего HTML запускается в небольшом имитаторе DOM/canvas/Web Serial. Команды идут в отдельный C++ процесс с настоящим кодом прошивки, ответы возвращаются обратно в студию. Проверены все одиннадцать страниц, запись групп и чтение результата, запрет изменения активного таймера, резервная копия с изображением, точное восстановление байтов фона и CRC, импорт старой темы, отклонение неверного проекта, сохранение черновиков соседних разделов, переподключение после обрыва.
- Проверена независимость разделов: некорректное поле в другом разделе не блокирует корректную запись текущего; изменения, сделанные на часах, перечитываются перед записью. Значения веса/шага округляются при переводе в целые единицы протокола.
- В HTML нет внешних скриптов, внешних стилей и сетевых запросов. Для запуска не нужен облачный сервис.

## Не подтверждено

Это не сборка Arduino-ESP32 для целевой платы. Совместимость реальных версий библиотек и физические USB/BLE, RTC, звук, сенсор, чтение/запись flash и дисплей нужно проверить на устройстве. Имитация DOM не является Chrome/Edge и не проверяет верстку, системный выбор порта и права браузера.

Настоящий браузерный прогон не состоялся: установка браузерного движка была остановлена недоступностью автоматической проверки разрешения инструмента. Ограничение не обходилось. Физических часов в среде нет.

Погрешность шагов, батареи и автономность не измерены. Четыре дня — цель, не результат испытаний. Зарядный контроллер аппаратный; проверка АКБ описана отдельно.

## Воспроизведение

Из корня распакованного комплекта: `python3 tests/run_studio_checks611.py`.

Перед повседневным использованием на плате: собрать прошивку с рабочим профилем платы, проверить подключение студии, изменение одного параметра и чтение результата, перезапуск и сохранение, импорт/экспорт фона, пять будильников и таймер, реальные уведомления телефона и звук при выключенных тихом режиме и «Не беспокоить». Зарядку малого аккумулятора проверять отдельно по аппаратным спецификациям.

## Проверки OSD 6.1

- Настоящий C++ обработчик: запись полного пакета из 85 байтов, чтение состояния, повторная загрузка NVS, отказ записи без изменения активной компоновки, отклонение повреждённого CRC, длины, HEX и выхода за экран. Повреждённая сохранённая компоновка игнорируется.
- Настоящий рендерер: каждый из 13 элементов отдельно, все допустимые размеры и крайние позиции у правой/нижней границы. Программно проверено отсутствие пикселей за объявленной областью. Секунды/таймер/специализация запрашивают нужные обновления экрана; остальные экраны не переходят в OSD.
- JavaScript и настоящий протокол прошивки через стенд: Pointer Events при масштабе экрана 2×, привязка к сетке, стрелки, отмена/повтор, отмена жеста, ограничения координат после увеличения размера, переключатели списка, сохранение и readback, отказ OSD-записи без capability OSD=1, экспорт/импорт проекта и отклонение неверных координат, сохранение OSD-черновика при применении другого раздела.
- Preview/OSD_Seven_Palettes.png — фактический программный растровый вывод прошивки, демонстрационные значения. Просмотрены семь палитр. Это не фотография устройства и не браузерный скриншот. CSS-верстка и системные Pointer Events настоящего браузера остаются непроверенными.

## Проверки исправления фона и мигания 6.7.0

- C++: составление нового фона/цифр не меняет видимый framebuffer физического дисплея до displayPresent; готовый кадр передаётся один раз, повторный вызов без изменений не передаёт кадр. Sleep/wake обращается к физическому LCD.
- Загруженный RGB565 фон реально отрисовывается, проверена доля смешивания, обычный циферблат и OSD. Отказ выделения canvas выбирает диагностируемый прямой режим без перезапуска.
- Отдельно проверены отсутствие файлового раздела, несмонтированный раздел и нехватка места. Форматирование не вызывается само при старте, не вызывается при отсутствии раздела и требует отдельной подтверждённой команды.
- Студия с настоящим обработчиком прошивки: ошибка обнаруживается до изменения других настроек, локальные параметры/картинка сохраняются, подготовка по явному действию и повторная загрузка завершаются проверкой CRC файла. Для отсутствующего раздела кнопка отключается и выдаётся инструкция по Partition Scheme; для нехватки места форматирование не предлагается как автоматическое исправление.
- Использованы имитаторы Arduino_Canvas, LittleFS и таблицы разделов. Это проверка логики приложения и рендерера; физическое SPI-время, реальная память PSRAM и сборка Arduino ещё не проверены. Ошибка на пользовательском снимке установлена; физическую причину несмонтированной LittleFS по одному снимку точно определить нельзя.
